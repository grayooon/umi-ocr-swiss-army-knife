# Windows 验证说明

## 当前状态与证据边界

维护者于 2026-11-03 确认 Windows 实测已完成，当前版本为 1.1.0 正式版。当前公开安装方案的最低目标系统为 Windows 10 x64，使用 Umi-OCR 自带 CPython 3.8 x64。

本次状态整理没有取得测试设备、确切 Windows/Umi 版本、依赖来源、模式覆盖和逐项日志，因而不将这些细节补写为“已通过”。自动化源码与发布工具回归也不能替代 Windows 原生 DLL、GUI 或真实图片识别验证。历史报告里的“待验收”只反映原审查日期的状态。

## Win7 边界

当前锁定的官方 ONNX Runtime 1.17.3 / 1.19.2 Windows wheel 存在系统 API 限制，安装器保留 Win7 依赖下载保护。本项目未提供已验证的 Win7 兼容二进制包。Windows 实测完成的确认不扩大为 Win7 全新部署支持，也不承诺未来发布 Win7 包。

已有兼容依赖不要被安装器覆盖。模型、Python ABI、系统接口和 DLL 构建需要同时匹配，不能仅靠改 DLL 名称或模型 IR 数字解决兼容性。

## 需要复现或报告问题时

以下是按需复验清单，不是未完成的发布门槛，也不是已通过结果表。

1. 记录 Windows 版本/位数、Umi-OCR/Python 版本、插件版本、依赖是沿用还是全新下载。
2. 完全退出 Umi-OCR，包括托盘程序，保留已能工作的目录备份。不要在运行时覆盖依赖。
3. 运行插件的 `tools/04_export_environment.bat` 留存本地环境报告；报告不会自动上传。
4. 用适合各插件的实际图片运行 `tools/02_self_check.bat`，核对识别内容；没有图片或没有文字不能当作通过。
5. 在 Umi 中验证实际使用的模型模式、插件切换、退出重启和断网识别；只记录实际测试的模式。
6. 如需验证迁移，将完整插件（含依赖和模型）复制到另一可写目录，检查中文/空格路径和默认模型定位。
7. 出错时记录完整报错和复现步骤，恢复已知可用备份。不要混用来源不明 DLL，也不要跳过 HTTPS 或哈希校验。

`[PASS]` 只说明自检获得非空结果及输入方式一致，文字正确性仍需核对；`[INCOMPLETE]` 不能作为完成记录；`[FAIL]` 应保留具体错误。环境报告只说明文件版本和内容指纹，不是安全或准确率认证。请勿上传隐私图片、业务验证码或账户信息。
