# 如何验证离线使用与联网边界

## 先明确要验证什么

本项目的目标是“下载阶段可以联网，识别阶段不需要联网、不上传识别图片”。源码可读和断网可用是两类证据，任何单独一项都不能证明所有依赖二进制永远没有恶意行为。本次附件没有模型和 site-packages，审查范围不能覆盖作者电脑上没有提交的文件。

## 普通用户：十分钟离线验证

1. 完成一个插件的安装。运行自检，用适合该插件的图片确认识别结果。
2. 把测试图片保存在本地磁盘，先不要用网络共享目录或网页图片。
3. 从托盘彻底退出 Umi-OCR，确保随后测试的是重新启动的程序。
4. 关闭 Wi-Fi 并拔掉网线，确认浏览器打不开一个需要实时访问的网站。
5. 启动 Umi-OCR，分别识别文字图片、车牌图片、验证码图片，并切换回前一个插件。
6. 对已经下载的各档模型重复识别；没有下载的档位应明确报缺模型，不能把失败记作通过。
7. 记录系统、Umi 和插件版本、模式、是否得到正确文字。不需要上传测试图片。

这能证明这些模式和这套文件可以离线工作。它没有证明“联网时绝不会发包”，也没有证明其他未知文件安全。

## 可选：联网条件下阻止识别程序出站

Windows 自带高级防火墙可以按程序阻止出站连接：按 Win+R，输入 `wf.msc`，进入“出站规则 → 新建规则 → 程序”，选择实际的 `UmiOCR-data\runtime\python.exe`，设置“阻止连接”，按实际网络配置文件应用并给规则命名。需要管理员权限时由电脑管理员操作。

如果还要验证整个 Umi-OCR 应用，应对实际运行的 Umi-OCR 启动程序建立相应规则。进程路径以你的安装位置和任务管理器所见为准，不要照抄别人的盘符。规则只针对所选程序，不必阻断其他 Python 环境。Win7 与 Win10 的界面文字可能略有区别。

设置后重新启动识别并重复测试。安装脚本使用同一个 runtime/python.exe，所以此规则也可能阻止你主动下载依赖；安装时可临时禁用这条自建规则，完成后恢复。不要为安装插件关闭整个防火墙或杀毒软件。

资源监视器的“网络”页可辅助查看连接，但一次观察没有看到连接不构成永久保证。维护者如需更强证据，可以结合防火墙日志或抓包记录，公布工具、规则、时间范围和实际执行的模式。

## 本候选版做了什么

| 位置 | 行为 |
| --- | --- |
| `tools/setup.py` | 用户主动启动才联网；HTTPS 下载；固定版本/大小/SHA-256；无 pip 引导执行 |
| `tools/assets.lock.json` | 清楚列出每个包/模型的来源、目标目录和散列 |
| `_bridge.py` | 调用 Umi 自带解释器；用 stdin/stdout 管道传输图像与结果；不监听端口 |
| `_runtime.py` | 不执行 site-packages 中的 `.pth`；禁用 ORT 遥测；阻止 Python 层 socket 网络事件 |
| `_worker.py` | 只接受三个固定后端之一；推理阶段不导入安装脚本 |
| `tools/environment_report.py` | 只生成本地版本/文件哈希报告，不自动上传，不收集用户名和绝对路径 |

微软说明，官方 Windows 版 ONNX Runtime 的遥测默认可能通过操作系统机制启用；因此本版显式禁用，而不是因为“模型本地运行”就假定依赖没有遥测。[ORT 隐私说明](https://github.com/microsoft/onnxruntime/blob/v1.19.2/docs/Privacy.md)、[Python API](https://onnxruntime.ai/docs/api/python/api_summary.html)

Python 网络审计钩子不能替代系统防火墙，原生 DLL 仍属于需要信任或限制的执行代码。哈希用于确认“与清单指定文件相同”，并不表示文件一定无漏洞或无恶意；清单本身也必须来自可信发布版本。

## 更新后要重新验证

升级代码、换依赖、换模型或换系统，都可能改变结论。保留旧发行包及其 SHA256SUMS，使用新版本单独测试。不要把某次“离线通过”截图用作以后所有版本的通用安全认证。
